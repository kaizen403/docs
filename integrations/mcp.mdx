OpenLinear exposes an MCP server from `apps/mcp`. The server runs as a stateless Cloudflare Worker, accepts Streamable HTTP requests at `/mcp`, and forwards each tool call to the OpenLinear API with the caller's personal access token (PAT).

Use the MCP server when an AI agent needs to read workspace or project context, create project structure, or turn a multi-phase implementation plan into OpenLinear issues.

## Connection

### Local development

Run the API and worker locally:

```bash
pnpm --filter @openlinear/api dev
pnpm --filter @openlinear/mcp dev
```

Set the API target for the local worker in `apps/mcp/.dev.vars`:

```bash
OPENLINEAR_API_URL=http://localhost:3001
```

Connect an MCP client to `http://localhost:8787/mcp`.

### Production

```json
{
  "mcpServers": {
    "openlinear": {
      "url": "https://mcp.openlinear.tech/mcp",
      "headers": {
        "Authorization": "Bearer ol_pat_0123456789abcdef0123456789abcdef"
      }
    }
  }
}
```

## Transport

The worker implements stateless Streamable HTTP. Each request creates a fresh transport — no session state survives across requests.

| Method | Path | Behavior |
|--------|------|----------|
| `POST` | `/mcp` | Handles MCP requests |
| `GET` | `/mcp` | Returns 405 (SSE sessions not supported) |
| `DELETE` | `/mcp` | Returns 204 |

## Authentication

Create a PAT from **Settings → API Keys** before connecting a client. OpenLinear shows the token once, stores only its hash, and lists token metadata after creation.

Send the token on every MCP request:

```
Authorization: Bearer ol_pat_0123456789abcdef0123456789abcdef
```

The worker only accepts PATs in the `ol_pat_<32 lowercase hex characters>` format. The API rejects revoked or expired PATs when the worker forwards a tool call. Wildcard `*` scope tokens satisfy all scope checks including the `tasks:write` requirement on bulk task creation.

## Tools

| Tool | Purpose |
|------|---------|
| `openlinear_list_workspaces` | List workspaces visible to the authenticated user |
| `openlinear_list_projects` | List accessible projects, optionally filtered by workspace or team |
| `openlinear_create_project` | Create a project and optionally attach one team |
| `openlinear_get_project` | Read one project by ID |
| `openlinear_list_teams` | List teams in a workspace or project |
| `openlinear_create_team` | Create a team inside a project |
| `openlinear_list_labels` | List project-scoped labels, including phase labels |
| `openlinear_create_label` | Create a project-scoped label |
| `openlinear_create_phase` | Create a project-scoped phase label following the phase naming convention |
| `openlinear_create_issue` | Create one issue in a project |
| `openlinear_update_issue` | Update issue fields such as title, status, labels, team, or due date |
| `openlinear_bulk_create_plan` | Create a project, phase labels, and tasks from one plan payload |

## Bulk Plan Flow

`openlinear_bulk_create_plan` is the preferred tool for turning a multi-phase plan into OpenLinear issues. Call it once with the full plan:

```json
{
  "workspaceId": "workspace-aeb35ae41ef68718e82d59f45ad0c447",
  "project": {
    "name": "Auth Overhaul",
    "description": "Migrate session auth to JWT + PAT",
    "key": "AO"
  },
  "phases": [
    {
      "name": "Foundation",
      "tasks": [
        { "title": "Add PAT model to schema", "priority": "high" },
        { "title": "Write migration", "priority": "high" }
      ]
    },
    {
      "name": "API Layer",
      "tasks": [
        { "title": "Implement /api/pats CRUD", "priority": "medium" },
        { "title": "Add PAT auth middleware", "priority": "high" }
      ]
    }
  ]
}
```

The tool:
1. Creates a project with status `planned`
2. If no `teamId` is provided, resolves an existing team from the project or auto-creates a default team
3. Creates one project-scoped phase label per phase
4. Calls the bulk task API once per phase to create tasks in the new project
5. Returns the project ID, project key, created task IDs, and per-phase failures

<Info>
`teamId` is optional. When omitted, the tool automatically resolves or creates a team so issue numbering and task creation always succeed.
</Info>

Bulk creation can be partially successful. Inspect the tool result for `failed` entries and `error` fields on phases before treating the plan as complete.

## Related API Surfaces

The MCP worker depends on these cloud API capabilities:

- PAT management at `/api/pats`
- Project and workspace reads plus project creation
- Team listing and creation
- Project-scoped label creation for phase labels
- Single-task create/update endpoints
- `POST /api/tasks/bulk` for plan expansion

See [API Reference](/reference/api) for the PAT and bulk task contracts.
